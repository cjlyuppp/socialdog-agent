# 两套数据口径对照

网页 agent 默认读取飞书每日同步快照（下称“飞书口径”）；历史数据模式读取 27 列历史交易表生成的回测包（下称“历史口径”）。两者的样本定义、金额字段和披露规则都不同。用历史数据对照 agent 的回答时，先看下表。很多数字差异来自口径不同，并不说明 agent 答错。

## 字段对应

| 概念 | 飞书口径（`query_aggregate` / `query_products`） | 历史口径（`history_aggregate` / `history_price_events`） | 能否直接比较 |
| --- | --- | --- | --- |
| 时间轴 | `下单时间`，Asia/Shanghai | `创建时间`，按 Asia/Shanghai 处理（来源未声明时区）；`收款时间` 不作时间轴 | 可以，分组定义相同 |
| 日 / 周 / 月 | `day` 为下单日期；`week` 为周一起始日期；`month` 为 YYYY-MM | 相同 | 可以 |
| 小时 / 星期 | 0–23 时；星期一 = 1 | 相同 | 可以 |
| 样本 | **支付观察**：`系统已支付` 且不是明确测试。**包含**全额退款订单 | **baseline**：整单已完成、全部为产品、无退款标记、无疑似重复、金额桥接无差异。**排除**有退款标记的订单。`all` 为全部来源记录（含取消、退单、充值） | 不能。baseline 剔除了退款单，支付观察保留了退款单 |
| 订单数 | `paid_observed_orders`：支付观察订单数 | `order_count`：不同订单编号数 | 样本不同，只能看趋势 |
| 主要金额 | `system_net_yuan` = 订单应付总额 − 已退金额，**含**钱包支付 | `recorded_receipt_yuan` = 收款金额列，**不含**余额扣除，也已扣掉优惠、积分、抖音/美团券 | 不能。历史口径少了钱包支付部分 |
| 成交前金额 | `订单应付总额`（未单独返回） | `recorded_deal_yuan` = 实际成交金额，未扣余额和券 | 近似对应，需店方确认 |
| 退款 | `cumulative_refund_yuan`：已知金额，记在原下单日 | 只有 `商品退款状态` 标记，退款金额和件数未知 | 不能 |
| 钱包 / 余额 | `wallet_original_debit_yuan`（钱包支付额） | `wallet_yuan`（扣除余额） | 概念相近，样本不同 |
| 优惠券 | `coupon_deduction_yuan`（优惠券减免）；`by=coupon_use` 区分是否用券 | `coupon_yuan`（优惠券抵扣分摊）；另有整单优惠、活动优惠、积分、抹零 | 仅优惠券一项可对照 |
| 配送方式 | `配送方式`，空值为“未记录” | `配送方式`，空值为“未记录”，不推定为自提 | 可以 |
| 渠道 | `销售来源` | 没有；`收款方式` 不是获客渠道 | 不能 |
| 顾客 | 匿名会员 ID（HMAC），游客 ID 不稳定 | 没有顾客 ID | 不能 |
| 商品名 | `商品明细.历史商品名称`，不合并相似名称 | `收费项目`，不合并相似名称 | 名称可能不一致，需人工对应 |
| 商品件数 | `recorded_quantity`：明细记录件数，不扣退款件数 | `recorded_quantity`：记录件数，不扣退款件数 | 可以，但样本不同 |
| 商品金额 | `item_net_yuan`：明细系统支付净额 | 按行分摊的 `recorded_receipt_yuan` | 不能，原因同“主要金额” |
| 商品价格 | 没有价格执行记录；`net_per_unit_yuan` 是单件净额，不是菜单价 | `项目单价`（来源标价），`history_price_events` 用它重建调价事件 | 只有历史口径能识别调价 |
| 单位 | 工具返回元 | 工具返回元（回测包文件内部存储为分） | 可以 |
| 披露规则 | 每组至少 20 位可确认会员 | 每组至少 N 个订单（默认 5，`--history-min-orders` 可调） | 不同：同一分组可能一边显示、一边隐藏 |
| 日数 | `days_in_scope`（日历天）和 `days_with_orders`（全店有支付观察订单的天） | 相同定义，按所选 scope 计算 | 可以 |
| 截断 | `research_assistant.py build --as-of`（工作簿来源） | `historical_backtest.py build --as-of` | 都会物理删除截断日之后的订单 |

## 对照时最常见的差异来源

1. **钱包支付**：飞书净额含钱包支付，历史收款金额不含余额扣除。储值消费占比高的时期，历史金额会明显偏低。
2. **退款单**：支付观察保留全额退款单（净额为 0，但计 1 单）；baseline 剔除整张有退款标记的订单。两边单量会不同。
3. **充值与非产品交易**：历史 `all` 含充值和快捷收款；baseline 不含。飞书订单表是否包含充值，需店方确认。
4. **疑似重复**：历史 baseline 剔除整张含疑似重复明细的订单，飞书口径没有这一步。
5. **披露门槛**：会员门槛和订单门槛各自隐藏不同的小组，展示出的分组加总不等于总计。

## 评测时的建议

- 判断 agent 回答对错，以同一口径的工具结果为准。自动评测（`eval_runner.py`）只拿历史口径的 golden 答案对照历史模式 agent，不跨口径比较。
- 想看两套口径在同一时期的差异，分别查询后并排列出，并注明上表中的差异来源。不要把差额解释为经营变化。
