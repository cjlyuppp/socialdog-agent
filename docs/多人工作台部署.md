# 多人研究工作台部署

## 安装与运行

Python 3.10 以上，建议 3.12。安装依赖和命令入口：

```sh
python3.12 -m venv .venv-api
. .venv-api/bin/activate
python -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
```

依赖由 `pyproject.toml` 维护，`requirements.txt` 安装项目及测试依赖。发布安装使用 wheel；修改源码后重新安装，或从仓库根目录直接运行 `python api_server.py`。

## 数据准备

准备同一份授权来源的完整历史包、带 `--as-of` 的截断包和独立核对库。所有生成物放在被 Git 忽略的 `outputs/` 或私有数据目录。

```sh
socialdog-history build --source /实际路径/历史交易表.xlsx --sheet 交易数据 --output-dir outputs/full
socialdog-history build --source /实际路径/历史交易表.xlsx --sheet 交易数据 --as-of 2023-03-15 --output-dir outputs/cut
socialdog-history verify --package outputs/full
socialdog-history verify --package outputs/cut
socialdog-api build-reference --package outputs/full --output outputs/reference/reference.sqlite --cutoff 2023-03-15
```

示例日期须替换为研究负责人确认的 T。原始工作表须严格匹配27个字段及顺序；多工作表或非 `Sheet1` 名称必须用 `--sheet` 指定。原始 Excel 保持不变，未知退款与顾客标识不补零。

模型仅接收截断包的工具结果。全量 `reference.sqlite` 由数据核对接口以 SQLite 只读连接访问，不传给 agent，不注册为工具。研究员的一般查询、日期和商品列表只含 ≤T；管理员可查询完整历史，跨 T 的同名分组分别列出截止日前后的行。核对 CSV 从已授权的查询结果生成。首次部署时核对库与截断包必须同源且 T 一致，后续发布按题库版本确定边界。

截断时删除的后续记录数量仅保存在离线manifest中，不进入新的模型工具结果或回答依据。离线golden核验应用同样的公开字段投影；原始审计文件不改写。

“研究规则”中可开启 `allow_post_cutoff_reference_after_submit`，默认关闭。开启后，仅已提交的本人测评可核对题目中指定的 T 后日期窗口和可选商品；未指定窗口的题目保持 ≤T。自由研究、提交前和其他人的测评均不解锁。关闭开关立即撤销额外访问。模型始终只读该题版本的截断包。

“题库管理”可修改 T、N 并发布。服务会在启动截断包的同级目录寻找同源完整包，校验 manifest 及原始 Excel 字节备份的 SHA256；按原清洗流程生成新的物理截断包，成功后原子启用新版本，不需要重启。T 只能在已导入数据的日期内选择。完整包不可用时，页面说明原因并禁止更改 T；服务端也拒绝。生成包保存在数据库旁的私有 `data-versions/`，需一并备份。原文件和运行中的旧包不改写。

题目、T、N 和数据版本共同生成不可变的题库版本。旧测评保留题目快照；旧派题使用原版本 T/N，并可从已生成包恢复运行。没有该版本待办的研究员不能新提交旧版本题目，也不能用任意版本编号查询数据。降低 T 或改变 N 后，对话的新任务不携带旧数据范围下的历史回答与依据。历史记录只回填能从原任务配置确认的 T/N，未知值保留空。

## 账号与模型

```sh
socialdog-api init-admin --username carrey --display-name Carrey --public-origin https://研究域名
python chat_agent.py --setup
```

`init-admin` 只允许在空工作区创建首位管理员，输出三天有效的一次性邀请。本人在浏览器设置至少10位密码；后续成员由管理员邀请。账号上限默认10（包括管理员），可在“额度与运行”配置为1–100且不得低于已有账号数；10名学生加2名管理员可设为12。密码以 Argon2 哈希保存，登录 cookie 为随机令牌，数据库只保存其 SHA256。重发邀请会立即撤销旧密码和已有登录会话，旧邀请失效。管理员不能停用自己、撤销自己的管理员权限或重置自己的密码；需要另一位管理员协助重置。

API Key 使用现有本机 `.env` 或环境变量配置，不写入数据库或前端。服务启动时读取模型配置；修改后重启服务。没有 Key 时数据核对仍可使用，提问与测评在创建任务前返回503，不伪造回答。

网页的研究对话和测评独立作答页可选择 DeepSeek Flash / V4 Pro，以及关闭、低、高、最高思考强度。选项由登录后的 `/api/models` 提供；浏览器按账号记住选择，未选时采用服务器 `.env` 默认值。后端只接受允许的模型和强度，不允许覆盖密钥或 API 地址。任务受理时保存配置，排队期间改变选择不影响已提交任务，回答信息显示实际模型和已记录强度。支持档位以 [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode/) 为准。

## 启动

生产环境：

```sh
socialdog-api serve --history-package outputs/cut --reference-db outputs/reference/reference.sqlite --public-origin https://研究域名 --frontend-dir frontend/dist
```

后端只监听 `127.0.0.1:8000`，由 HTTPS 反向代理将同源网页与 `/api` 请求转发至此端口。`--public-origin` 必须与浏览器访问的来源地址完全一致。保留默认 Secure、HttpOnly、SameSite=Lax cookie；不要将服务直接改为公网监听。运行一个进程，不使用多 worker；数据库文件锁会拒绝同一工作区的第二个服务。

本机 HTTP 开发：

```sh
socialdog-api serve --history-package outputs/cut --reference-db outputs/reference/reference.sqlite --public-origin http://127.0.0.1:8000 --local-http
```

此时后端直接提供 `frontend/dist`，没有 MSW。也可用 Vite 代理：后端的 `--public-origin` 设为 `http://127.0.0.1:5173`，前端执行 `VITE_USE_MOCK=0 VITE_API_PROXY=http://127.0.0.1:8000 npm run dev -- --host 127.0.0.1`。从模拟开发切换时关闭旧模拟标签页，使用新的浏览器会话，避免旧 Service Worker 拦截请求。

## 任务与费用口径

- 每人最多一个排队或运行中的任务，全站并发上限可配置；排队任务也预占额度。
- 管理后台可逐人设置测评预留次数，不得超过每日上限。旧账号默认预留0次；设为正数后，自由研究最多使用“每日上限−预留”，测评可用尚未消耗的总额度。全站上限仍适用于测评。变更即时生效，已受理任务不撤回。
- “额度与运行”可配置新成员的默认每日额度和测评预留，默认30/0；新建账号也可单独填写。默认值的修改不追溯已有账号。
- 任务、对话和配额预占在同一个 SQLite 写事务提交，超额返回429，不调用模型。
- 配额按 Asia/Shanghai 的任务受理日统计；每个受理任务计一次，失败不返还，避免重复失败请求绕过调用限制。HTTP请求被拒绝不计额度。
- 每次模型调用开始前写入账本，返回后保存原始 usage、模型和响应编号。工具选择、回答生成、数字改写及失败调用均有单独记录。
- 模型未返回 usage 或调用中断时，用量和费用显示未知，不能当作零；其他成功调用的原始 usage 仍保留在账本。
- 服务商输入、输出单价默认留空；填入默认模型的实际单价后才估算费用。其他模型或混合模型汇总费用显示未知，token仍正常累计。按当前设置估算，不等于历史结算账单。费用与 token 按所属任务受理日归属。
- 重启后未完成任务标记为错误，不自动重试。完整会话、评分和已记录的 usage 保留。

## 正式题库

默认没有题库。管理员在“题库管理”填写名称、T/N、题目分类、标题、问题、参考数据和可选提交后核对窗口，先保存草稿，再发布。草稿对研究员不可见；旧版本可复制为新草稿，已发布记录不直接编辑。同一草稿被另一管理员修改时返回409，需重新加载。首次部署也可用 `--question-bank /私有路径/questions.json` 导入 JSON 数组；一旦有已发布题库，重启时 CLI 文件不会覆盖后台版本：

```json
[
  {
    "id": "coverage",
    "category": "quality",
    "title": "数据范围",
    "question": "当前数据覆盖什么时间？",
    "reference_hint": null
  }
]
```

分类支持 `time_series`、`product`、`price_event`、`quality`、`unavailable`、`out_of_sample`。`reference_hint` 可预设样本、分组、日期或商品；不包含标准答案。模型只接收题目，不接收参与者先写下的答案。回答成功后才能评分，每次测评只接受一次评分。

管理员在“派题与进度”选择研究员、题目和可选截止日期（上海日期，当天结束前可提交）。同一版本的同一道题不重复分配。研究员默认首页有未交题目时进入“我的待办”，否则进入研究对话。保存独立答案并受理任务即计为“已提交”；模型失败不抹去独立答案，进度不以评分或模型成功作为完成标准。待办和“我的研究→作答记录”均可恢复已提交记录。

## 反馈、研究想法与复核

模型回答旁可提交问题反馈；测评评分可一次附加多条问题。每条记录环节、描述、可选正确做法和依据引用，服务端保存原问题、回答及完整依据快照，不接受客户端伪造上下文。评分及其附加问题在同一事务保存，重复评分不会重复生成反馈。

管理员在“问题复核”按来源、环节、研究员和状态筛选，标记成立、不成立或待讨论并写备注。仅成立的反馈进入 JSON 模型改进清单。按人汇总中，成立比例的分母仅含“成立+不成立”，待复核和待讨论不计入；无已判定记录时显示未知。测评分数明确表示学生对研究助理的评分，不是学生研究能力的自动成绩。

研究员在“我的研究”提交研究问题、数据、初步发现和下一步，并关联自己的对话。“研究规则”可修改四个字段的名称、提示和必填规则（研究问题始终必填），还可填写双方可见的邀请参考标准。服务端按当时规则校验，提交保存表单及标准快照。审核人手动选择待审、已反馈、邀请加入或暂不合适；研究员可以回看状态及反馈。状态不自动授予账号权限或决定正式项目资格。

首次登录展示使用须知，确认记录按账号和版本保存；数据范围中常驻说明管理员及获授权审核人可查看内容。只读对话查看接口验证成员与会话归属，并要求成员已确认须知，普通会话接口保持本人隔离。在“成员与权限”可分别授予 `review_feedback`（问题复核和改进清单）、`review_ideas`（想法审核）、`view_researchers`（档案和对话）。这些权限独立、立即生效及撤销；审核人无法管理账号、设置额度、发布题库或获得完整核对数据。管理员拥有全部管理权限。

正式题库内容、T/N 和加入标准仍由研究负责人填写。`anonymous_ab_evaluation` 默认关闭，可在“研究规则”开启：新作答固定随机 A/B 顺序，分别收集两份答案的四项评分，提交后揭示来源和模型依据，再允许反馈模型问题；旧作答不受开关变化影响。模型评分映射回原 `scores`，同时保存 `anonymous_scores`。这仅隐藏来源标签，参与者可能认出自己的答案，不能据此宣称完成严格双盲或外部准确率验收。

## 验证与维护

```sh
python -m unittest test_chat_agent test_research_assistant test_feishu_agent_source test_feishu_daily_clean test_factor_inspection test_web_agent test_historical_backtest test_history_agent test_api_server test_research_workspace test_admin_configuration -v
socialdog-api openapi --history-package outputs/cut --output docs/openapi.json
cd frontend
npm run typecheck
npm run check:api
npm test
npm run build
```

API集成测试使用真实 ASGI 请求、SQLite、任务队列和历史工具，只替换外部模型响应。它们不证明真实 DeepSeek 的回答质量；需要额外运行 `eval_runner.py` 和人工评审。

OpenAPI 文件由实际应用导出，Python 测试核对其与运行时契约一致；`check:api` 对照前端 TypeScript 的字段、JSON 类型和枚举。安装后的命令从当前工作目录读取 `.env`、`research_local/` 及飞书同步状态；切换工作区时先切换目录，不向安装包目录写入密钥或数据。

备份 `research_local/`、授权数据包和题库，保留文件权限。工作区数据库默认 `research_local/workspace.sqlite`，权限0600。运行时备份 SQLite 应使用 SQLite backup API；停机后可整体备份数据库及其 WAL 文件。邀请链接、账号数据、审计记录和 `.env` 不进入公开仓库。

数据库由 `socialdog_agent/server/migrations/` 中的有序 SQL 脚本管理。启动时在单个事务内执行未应用的迁移；失败时回滚，未知版本拒绝启动。v1→v2 补充关闭的测评数据访问配置；v2→v3 新增研究工作流；v3→v4 新增审核权限、题库草稿/当前版本指针、表单快照及固定 A/B 模式，不重建现有表或清空记录。升级前先停服务并备份数据库；旧版本程序不支持读取升级后的新版本数据库，回滚程序时应使用对应的升级前备份。
